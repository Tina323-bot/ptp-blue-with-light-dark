Technical & Business Implementation Notes

0. Intelligence Engine Selection

  • Selected engine: Mock JS Engine.
  • Rule behavior is deterministic front-end simulation for stable PM demo alignment.
  • OCR, duplicate checks, currency mismatch checks, user confirmation, and PDF preview are simulated in browser JavaScript.

1. Core Rule Logic

  • IF the user has not chosen Copy existing IO ticket or Create new THEN the OACP submission cannot move to scenario confirmation.
  • IF payment scenario, payment type, and payment method are not confirmed THEN invoice upload remains blocked.
  • IF OCR has only matched Company Name and Vendor Name THEN only those two Header info fields are populated with top-five dropdown candidates.
  • IF the user confirms Company Name and Vendor Name THEN the demo completes the remaining invoice fields from OCR plus matched historical OACP invoices.
  • IF currency, duplication, or bank info alerts exist THEN show them in the conversation Compliance alerts block.
  • IF every compliance alert is confirmed THEN the conversation can continue to final invoice information review and Submit.
  • Pending business confirmation: production rule coverage should confirm exact similarity thresholds, supplier master lookup, bank validation freshness, duplicate matching keys, and alert override audit policy.

2. AI Module Inventory

  • AI-OCR: simulates reading supplier invoice PDF, first matching Company Name and Vendor Name, then filling the remaining invoice fields after user confirmation. Production integration: OCR service plus invoice ingestion service.
  • AI-Compliance: checks extracted and historically matched facts against currency, duplicate, and bank info rules. Production integration: rule engine, ERP/procurement history, supplier master, bank validation service, and workflow engine.
  • AI-NLU: keeps the submission process inside a chat-style interaction. Production integration: LLM/NLU service and workflow orchestration.

3. Data Handoff Specification

  • Fake demo data: IO ticket start mode, payment scenario, payment type, payment method, invoice PDF file name, OCR fields, top-five Company/Vendor candidates, channel history, duplicate invoice records, currency baseline, bank validation state, and supplier invoice preview.
  • Production fields: IO ticket mode, company name, vendor name, payment scenario, payment type, payment method, channel, invoice number, PO number, amount, currency, invoice date, due date, tax ID, attachment ID, submitter, alert confirmations, validation status, and override reason.
  • User-provided data: scenario radio selections, PDF upload through file picker or drag-and-drop, Company/Vendor dropdown confirmation, alert confirmations, and final invoice confirmation.
  • System-sourced data: historical invoice numbers, Company/Vendor similarity candidates, supplier trading currency, PO reference, supplier master, bank validation status, and workflow state from ERP/procurement systems.
  • Pending DT/business confirmation: exact source system for OACP, LGAP, Ariba, and SDMS history lookup and whether PDF preview is stored in document service or ERP attachment table.

4. Tech Spec & User Flow

  • Entry: Smart AI Agent home page with four channel cards: OACP, LGAP, Ariba, SDMS.
  • Current page: channel-specific invoice submission workspace with common layout across all channels.
  • Local state actions: route selection, Copy existing IO ticket, Create new, scenario radio confirmation, upload modal, OCR simulation, Company/Vendor dropdown selection, alert confirmation, field editing, PDF preview modal, chat message entry, Confirm, and Submit invoice.
  • Downstream endpoint: validated invoice submission task, exception review, or archive state.
